# M10：基于证据的 AI 推荐说明

## 状态

待验收。

## 模块目标

使用 DeepSeek 把已经由推荐算法计算完成的价格、评分、设施匹配、平台覆盖、优势、取舍和风险，
改写成更自然的中文推荐说明。AI 不参与候选筛选和排序，也不能修改结构化证据。

本模块采用按需调用：生成推荐后，用户点击“生成 AI 推荐说明”才会产生模型请求，避免每次调整都
自动消耗额度或因为模型响应变慢而阻塞基础推荐。

## 接口

```text
POST /api/v1/recommendations/{session_id}/explanations
```

同一个推荐会话只生成一次。再次请求直接读取 MySQL 中已有的短说明，不重复调用 DeepSeek。

## 证据边界

- 输入只包含已经保存的推荐结果和评分证据。
- DeepSeek 返回的 `listing_public_id` 必须与输入集合完全一致。
- 返回内容经过 JSON、长度和重复 ID 校验。
- 排名、总价、评分和算法理由始终来自后端，不采用模型计算结果。
- DeepSeek 未配置、超时、输出非法或返回陌生 ID 时，使用本地证据模板生成说明。
- 页面继续展示原始算法理由、取舍和风险，AI 文案不能覆盖它们。

## MySQL 存储控制

只保存每个结果不超过 300 字的自然语言说明，以及会话级 Provider、模型名、Token 数量和错误码。
不保存完整 Prompt、DeepSeek 原始响应或重复推荐快照。推荐调整仍创建独立会话，并只保存字段差异。

大型历史快照和长期分析数据不进入本模块；业务量扩大后按月归档到对象存储或冷数据表。

## 无 Key 验收

1. 保持 `AI_PROVIDER=local`。
2. 创建一组有结果的推荐。
3. 点击“生成 AI 推荐说明”。
4. 页面应显示“本地证据说明”，每张卡片出现自然说明。
5. 原始排名、分数和理由不发生变化。

## DeepSeek 验收

1. 在 `backend/.env` 配置 `AI_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY` 后重启后端。
2. 创建一组有结果的推荐并点击“生成 AI 推荐说明”。
3. 页面应显示“DeepSeek 已生成”。
4. 说明只能引用卡片已有事实，并同时保留原始证据列表。
5. 再次调用相同接口，确认直接返回保存结果，不产生第二次模型调用。

## 不包含

- AI 修改推荐排序。
- 从互联网补充民宿事实。
- 旅行日程草稿生成。
- 评论主题与情绪分析。
- 自动归档任务；归档将在数据治理模块实现。
