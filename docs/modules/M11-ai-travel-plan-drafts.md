# M11：AI 旅行计划草稿

## 状态

待验收。

## 模块目标

基于已经保存的推荐会话生成旅行计划草稿。输入只包括城市、入住和离店日期、人数、用户偏好以及
推荐民宿所在区域。计划是可编辑建议，不代表景点、交通、营业时间或预订已经确认。

## 接口

```text
POST /api/v1/recommendations/{session_id}/travel-plan
```

同一个推荐会话只保存一份草稿。重复调用直接读取 MySQL，不再次调用 DeepSeek。

## 数据与安全边界

- 最多生成 14 天计划，每天最多 5 项活动。
- DeepSeek 返回日期必须完整覆盖入住日至离店日，不能重复或增加其他日期。
- 景点开放时间、距离、价格和交通班次等未知信息必须标记为“待确认”。
- DeepSeek 调用失败或未配置 Key 时，自动生成本地基础草稿。
- 不保存完整 Prompt 或模型原始响应。
- MySQL 只保存经过 Pydantic 校验的计划 JSON、摘要、Provider、模型和 Token 审计字段。
- 草稿不会覆盖推荐会话，也不会修改民宿排序。

## MySQL 表

`travel_plan_drafts`：

- `recommendation_session_id`：关联推荐会话并设置唯一约束。
- `payload`：经过限制的结构化天数和活动。
- `summary`：不超过 300 字的草稿摘要。
- `provider`、`model`、Token 字段与 `error_code`：轻量调用审计。

推荐会话删除时草稿随之删除，不产生无法关联的孤立数据。

## 无 Key 验收

1. 保持 `AI_PROVIDER=local` 并重启项目。
2. 生成一组推荐结果。
3. 点击“生成旅行计划草稿”。
4. 页面应展示按日期排列的草稿，Provider 显示 `local`。
5. 每一项应提示交通、时间或具体地点仍需确认。

## DeepSeek 验收

1. 配置 `AI_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY` 后重启后端。
2. 创建新的推荐会话并生成旅行计划。
3. Provider 应显示 `deepseek`，日期必须与入住和离店范围完全一致。
4. 再次点击时应返回同一份草稿，不重复消耗 Token。

## 不包含

- 地图路线和实时交通。
- 景点门票或民宿自动预订。
- 航班、铁路和天气实时查询。
- 多版本草稿编辑历史。
- 评论主题和情绪分析。
