# M8：推荐解释与反馈调整

## 状态

已验收，后续开发已进入 M9。

## 模块目标

在 M5 可解释评分基础上补充妥协与风险说明，并允许用户用一句受约束的反馈调整偏好、重新计算推荐。反馈不会直接改写分数或民宿事实，而是先转换成结构化条件，再重新调用同一推荐引擎。

## 已实现

- 每条推荐增加 `tradeoffs`，说明超预算、设施缺失或区域不匹配。
- 每条推荐增加 `risk_notes`，说明评分不足或平台覆盖样本较少。
- 支持“想便宜一点”“更想看海”“住双廊镇”“改成家庭出行”等反馈。
- 支持从反馈中调整预算、旅行风格、设施和区域。
- 无法识别的反馈保留原条件并返回警告。
- 每次调整创建新的推荐会话，不覆盖原结果。
- 调整前会话、调整后会话、原始反馈和结构化变化保存到 MySQL。

## API

```http
POST /api/v1/recommendations/{session_id}/adjust
```

请求示例：

```json
{
  "feedback": "更想看海，最好住在双廊镇"
}
```

返回原会话编号、新会话编号、应用的字段变化、警告和新的完整推荐结果。

## 数据库

- `recommendation_results` 新增 `tradeoffs` 和 `risk_notes`。
- 新增 `recommendation_adjustments` 保存反馈调整链路。
- 迁移会为历史推荐结果安全回填空数组，不破坏已有会话。
- Alembic 版本：`959003427db3`。

## 前端

推荐结果上方新增“还想怎么调整？”输入框。调整成功后，页面直接替换为新的推荐会话，并展示新的排序、理由、妥协和风险。

## 真实验证

初始省钱型推荐第一名为 `DL_000002`。输入“更想看海，最好住在双廊镇”后：

- 应用 `scenery` 风格。
- 增加 `sea_view` 设施偏好。
- 区域调整为双廊镇。
- 新第一名变为 `DL_000003`。
- 明确提示超预算 425 元。
- 明确提示当前仅覆盖 2 个平台。
- 创建新的推荐会话并保存调整记录。

## 不包含

- 外部大模型自由生成推荐结论。
- 多轮长期对话记忆。
- 用户账号级反馈历史。
- 基于点击行为训练排序模型。
- 修改价格、评分或平台原始事实。

## 验收步骤

1. 打开 `http://127.0.0.1:5173/recommendations`。
2. 使用默认条件生成推荐，确认第一名为苍山慢居庭院。
3. 检查结果中出现平台覆盖风险提示。
4. 在“还想怎么调整？”输入“更想看海，最好住在双廊镇”。
5. 点击“调整推荐”。
6. 确认第一名变为月白·双廊海景民宿。
7. 确认页面显示超预算 425 元和仅覆盖 2 个平台。
8. 确认页面底部推荐会话编号发生变化。
9. 输入无法识别的反馈，确认原推荐不会丢失。
10. 在 Swagger 中调用调整接口，检查 `applied_changes`。
11. 执行 `scripts\dev.ps1 test`，确认全量检查通过。

## 通过条件

- 推荐优势、妥协和风险均来自真实结构化数据。
- 用户反馈会转成受支持字段并真正重新计算。
- 原推荐会话不被覆盖，前后调整链路可追溯。
- 无法识别或请求失败时保留原结果。
- 已验收模块没有回归。
