# M6：前端个性化推荐体验

## 状态

已验收，后续开发已进入 M7。

## 模块目标

将 M5 的可解释推荐接口接入 Vue 3，形成从填写旅行条件、选择偏好到查看推荐排序和评分依据的完整前端闭环。

本模块不调用外部大模型。页面展示的分数与理由全部来自 M5 的确定性推荐引擎，不在浏览器中重复计算或伪造推荐结论。

## 页面入口

```text
http://127.0.0.1:5173/recommendations
```

民宿搜索页的主导航也增加了“智能推荐”入口。

## 已实现功能

### 旅行基础条件

- 目的地城市。
- 入住和离店日期。
- 入住人数。
- 入住总预算。
- 离店日期最早为入住次日；入住日期后移时，离店日期自动顺延。
- 前端日期和预算基础校验。

### 旅行风格

页面提供四种互斥风格：

- `value`：精打细算。
- `comfort`：住得舒服。
- `scenery`：为风景停留。
- `family`：全家出发。

页面只负责收集用户选择，实际权重由后端推荐引擎统一控制。

### 显式偏好

- 设施：无线网络、空调、厨房、洗衣机、停车位、海景和低楼层。
- 区域：大理镇和双廊镇。
- 按钮使用 `aria-pressed` 表达选中状态，支持键盘操作。

### 推荐结果

每条结果展示：

- 推荐名次、民宿名称和所在区域。
- 可比较的平台数量。
- 入住总价和最高平台评分。
- 后端生成的推荐理由。
- 综合匹配分。
- 价格、评分、设施、平台覆盖和区域五项得分。
- 推荐算法版本和已保存的会话编号。

### 页面状态

- 初始引导状态。
- 推荐计算中的加载状态。
- 请求失败和重试状态。
- 无候选状态，不使用无报价民宿填充结果。
- 成功结果状态。

## 接口

页面调用：

```http
POST /api/v1/recommendations
```

请求使用驼峰形式的前端类型，并在 API 模块中转换为后端要求的蛇形字段。响应分数和历史会话编号直接使用后端返回值。

## 自动测试

M6 新增 4 项前端测试：

- 默认条件能够提交并展示推荐结果和解释。
- 旅行风格、设施和区域偏好能够正确发送。
- 没有可订候选时显示明确空状态。
- 错误日期在前端拦截，不调用 API。

项目当前共有 9 项前端测试和 25 项后端测试。

## 响应式验证

- 桌面端采用偏好工作台和横向推荐评分卡。
- 移动端将旅行风格改为双列，结果摘要和评分区域纵向排列。
- 使用 390 × 844 视口验证，页面没有横向溢出。
- 桌面端和移动端真实调用推荐 API 均能展示推荐结果。
- 浏览器控制台没有错误或警告。

## 不包含

- 自然语言需求解析和外部大模型调用。
- 对话式修改偏好。
- 用户登录、收藏和长期偏好。
- 地图、景点和旅行计划。
- 在推荐结果页直接完成真实平台预订。

## 验收步骤

1. 启动项目并打开 `http://127.0.0.1:5173/recommendations`。
2. 确认默认目的地为大理市，日期为 2026 年 10 月 2 日至 5 日。
3. 选择“精打细算”，点击“生成我的推荐”。
4. 确认返回 3 条结果，第一名为 `DL_000002` 对应的民宿。
5. 检查每条结果包含推荐理由、综合分和 5 项分项得分。
6. 改选“为风景停留”并选择“海景”，再次生成推荐。
7. 确认海景民宿排名提升，页面选中状态保持正确。
8. 将离店日期改为早于入住日期，确认页面提示错误且不提交。
9. 使用没有演示报价的日期，确认页面显示无候选状态。
10. 将浏览器缩窄至手机宽度，确认表单和评分卡仍可操作。
11. 执行 `scripts\dev.ps1 test`，确认全部检查通过。

## 通过条件

- 用户可以通过页面提交 M5 支持的全部核心推荐条件。
- 页面不自行编造分数、理由或民宿报价。
- 修改旅行风格和偏好后，请求参数与结果排序相应变化。
- 加载、错误、空数据和成功状态均有明确反馈。
- 桌面端和移动端没有内容遮挡或横向溢出。
- 已验收的搜索、比价、导入和推荐 API 没有回归。
