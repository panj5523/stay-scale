# M7：自然语言需求解析与确认

## 状态

已验收，后续开发已进入 M8。

## 模块目标

允许用户用一句中文描述旅行需求，将文本转换为经过 Pydantic 校验的结构化偏好，并在用户确认后再进入 M5 推荐引擎。

M7 采用本地、确定性、可解释的中文规则解析器作为第一版基线。它不依赖外部大模型和 API Key；后续选择模型供应商时，可以替换解析提供者，但继续复用当前的校验、证据、确认和降级流程。

## 处理流程

```text
用户输入自然语言
  -> 本地解析器提取字段
  -> Pydantic 校验
  -> 返回证据、置信度、缺失项和警告
  -> 自动填入可编辑表单
  -> 用户检查并修改
  -> 确认结果保存到 MySQL
  -> 调用可解释推荐引擎
```

未经用户确认的解析结果不会直接进入推荐计算。

## 可识别字段

- 目的地城市：当前内置大理、丽江和昆明别名，也支持明确的城市名称。
- 入住和离店日期：支持 ISO 日期及“2026年10月2日到5日”等中文范围。
- 人数：支持数字及一至十的常见中文表达。
- 入住总预算：支持“预算1600”“1600元以内”等表达。
- 设施：无线网络、空调、厨房、洗衣机、停车位、海景和低楼层。
- 区域：当前演示数据支持大理镇和双廊镇。
- 旅行风格：省钱、舒适、观景和家庭。
- 风险厌恶：可取消、行程可能变化、不可退等表达。

## 可解释性与降级

每个识别字段保存原文证据和标准化值。例如“看海”会形成旅行风格或海景设施的证据。响应同时包含：

- `confidence`：本次规则解析的覆盖置信度。
- `evidence`：字段、匹配原文和标准化结果。
- `missing_fields`：仍需用户补充的必要字段。
- `warnings`：日期无效或信息不足等提示。
- `parser_name` 与 `parser_version`：用于追踪解析来源。

解析失败或服务不可用时，前端保留下方结构化表单，用户仍可手动填写并生成推荐。

## 数据库

新增 `preference_parse_sessions`：

- 原始自然语言。
- 解析器名称和版本。
- 置信度。
- 初始解析结果。
- 提取证据、缺失项和警告。
- 用户最终确认结果。
- `needs_confirmation` 或 `confirmed` 状态。
- 创建和确认时间。

迁移版本：`e98b0858110c`。

## API

### 创建解析会话

```http
POST /api/v1/preference-parses
```

示例：

```json
{
  "text": "两个人去大理，2026年10月2日到5日，预算1600以内，想要高性价比，最好有无线网络和厨房。"
}
```

返回 HTTP 201 和待确认的结构化草稿。

### 读取解析会话

```http
GET /api/v1/preference-parses/{session_id}
```

### 确认解析结果

```http
PATCH /api/v1/preference-parses/{session_id}/confirm
```

确认请求必须包含城市、入住日期、离店日期和人数，日期仍需满足离店晚于入住。

## 前端

推荐页新增“先用一句话，说出你想怎么住”区域：

- 输入或修改自然语言。
- 点击“识别并填入条件”。
- 查看证据、置信度和缺失项。
- 在原有表单继续修改识别结果。
- 点击“确认偏好并生成推荐”完成保存和推荐。
- 解析失败时继续手动填写。

入口：`http://127.0.0.1:5173/recommendations`。

## 自动测试

- 完整中文需求的字段提取与证据。
- 家庭风格优先级、设施识别和缺失项。
- 倒序日期安全降级。
- 数据库置信度约束。
- 创建解析和确认接口。
- 不完整确认请求返回 HTTP 422。
- 前端解析、自动填表、确认后推荐。
- M0 至 M6 全量回归。

## 真实验证

使用完整中文需求验证：

- HTTP 创建解析返回 201。
- 城市、日期、2 人、1600 元预算、无线网络、厨房、大理镇、省钱风格和高风险厌恶全部正确。
- 返回 10 条提取证据，无缺失字段。
- 确认返回 200，状态变为 `confirmed`。
- 历史读取保持确认状态。
- 浏览器默认示例展示 8 项证据并成功生成 3 条推荐。
- 390 × 844 视口无横向溢出，控制台无错误。

## 不包含

- OpenAI、DeepSeek 或其他外部模型调用。
- 多轮对话和上下文记忆。
- 从评论中推断用户偏好。
- 风险偏好参与 M5 排序扣分。
- 用户账户下的长期偏好画像。

## 验收步骤

1. 打开 `http://127.0.0.1:5173/recommendations`。
2. 保留默认自然语言，点击“识别并填入条件”。
3. 确认显示 8 项证据、98% 置信度和 `zh-rules-v1`。
4. 确认城市、日期、人数、预算、无线网络、厨房和省钱风格已填入表单。
5. 手动修改一项条件，例如人数或预算。
6. 点击“确认偏好并生成推荐”。
7. 确认成功显示 3 条推荐，修改后的值参与请求。
8. 输入“想去大理看海”，确认页面提示日期和人数仍需补充。
9. 输入倒序日期，确认日期不会直接写入表单。
10. 停止后端后再次识别，确认页面提示降级且手动表单仍可使用。
11. 在 Swagger 中读取解析会话并确认状态和证据可以追溯。
12. 执行 `scripts\dev.ps1 test`，确认全量检查通过。

## 通过条件

- 解析输出可见、可编辑，并经用户确认后才进入推荐。
- 错误或不完整输出不会直接进入推荐计算。
- 每个解析结果可以追溯解析器版本和原文证据。
- 外部 AI 不可用或未配置时，基础表单和推荐仍可使用。
- 解析会话可以保存、确认并重新读取。
- 桌面端和移动端均可操作。
