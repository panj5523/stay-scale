# M2：民宿查询与跨平台比价 API

## 状态

待验收。

## 模块目标

基于 M1 的统一民宿、平台房源、房型和价格快照，提供前端可直接使用的民宿搜索与报价详情接口。该模块只提供只读业务 API，不接入真实平台采集，也不实现前端业务页面或 AI 推荐。

## API

### 搜索与比价

```http
GET /api/v1/listings
```

必填参数：

| 参数 | 说明 |
| --- | --- |
| `city` | 目的地城市，当前演示数据为“大理市” |
| `check_in` | 入住日期，格式 `YYYY-MM-DD` |
| `check_out` | 离店日期，必须晚于入住日期 |

可选参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `guests` | `2` | 入住人数，范围 1 至 20 |
| `district` | 无 | 区域精确筛选 |
| `keyword` | 无 | 民宿名称或地址关键词 |
| `facility` | 无 | 设施代码，可重复传递，多个设施采用“同时具备”语义 |
| `min_price` | 无 | 最低总价下限 |
| `max_price` | 无 | 最低总价上限 |
| `sort` | `price_asc` | `price_asc`、`price_desc` 或 `rating_desc` |
| `page` | `1` | 页码 |
| `page_size` | `20` | 每页数量，最大 50 |

搜索结果以统一民宿为单位，返回平台数量、可用报价数量、最低入住总价、最高平台评分和标准化设施。

### 民宿报价详情

```http
GET /api/v1/listings/{public_id}
```

必填查询参数为 `check_in` 和 `check_out`，`guests` 默认为 2。返回统一民宿信息及各平台的房型报价，报价按总价从低到高排列，并保留费用明细、优惠条件、取消政策、库存和采集时间。

## 价格选择规则

- 只选择与入住日期、离店日期和人数完全匹配的价格快照。
- 只返回仍标记为可订的价格。
- 房型最大入住人数必须不小于查询人数。
- 同一房型只采用最新采集时间的价格；同一时间存在多种价格类型时全部保留。
- 列表价格表示整个入住区间的最低总价，不是单晚价格。
- 当前 M2 只比较 `CNY` 演示报价，暂不进行跨币种换算。

## 模块结构

```text
HTTP Router -> ListingService -> ListingRepository -> MySQL
                 |
                 +-> Pydantic 请求与响应模型
```

- Router：参数接收、响应模型和 404 处理。
- Service：分页响应、设施和平台报价的业务组装。
- Repository：最新价格快照、筛选、聚合、排序和分页查询。
- Schema：日期、人数、价格区间、分页与排序约束。

## 演示请求

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/listings?city=%E5%A4%A7%E7%90%86%E5%B8%82&check_in=2026-10-02&check_out=2026-10-05&guests=2"

Invoke-RestMethod "http://127.0.0.1:8000/api/v1/listings/DL_000001?check_in=2026-10-02&check_out=2026-10-05&guests=2"
```

也可以打开 `http://127.0.0.1:8000/docs`，在 Swagger UI 中直接填写参数测试。

## 自动验证

- 请求日期和价格范围校验。
- 重复设施参数去重。
- 搜索分页响应契约。
- 民宿不存在时返回 HTTP 404。
- 真实 MySQL 的城市搜索、设施筛选、价格筛选、排序和分页。
- 真实 MySQL 的统一民宿到平台房型报价详情。
- M0 健康检查和 M1 数据模型测试无回归。

## 不包含

- 真实美团、途家、木鸟的数据抓取或官方 API 对接。
- 自动判断两个平台房源是否为同一家民宿。
- 前端搜索、筛选和民宿详情页面。
- 用户登录、收藏、订单和支付。
- 个性化推荐、AI 推荐和旅行规划。

## 验收步骤

1. 在项目根目录运行 `start-dev.cmd`。
2. 打开 `http://127.0.0.1:8000/docs`，找到 `listings` 分组。
3. 使用“大理市”、`2026-10-02`、`2026-10-05` 和 2 人执行搜索。
4. 确认返回 3 个统一民宿，并按最低总价升序排列。
5. 添加 `facility=sea_view`，确认只返回 `DL_000003`。
6. 查询 `DL_000001` 详情，确认返回 4 条平台房型报价且按总价升序排列。
7. 将离店日期设置为早于入住日期，确认接口返回 HTTP 422。
8. 执行 `scripts\dev.ps1 test`，确认全部自动化测试和前端构建通过。

## 通过条件

- 搜索、筛选、排序、分页和详情接口响应稳定。
- 比价以统一民宿为单位，不把不同平台房源错误显示成不同民宿。
- 报价包含完整费用和优惠信息，最低总价计算正确。
- 参数错误返回 422，民宿不存在返回 404。
- 现有启动、健康检查、数据库迁移和演示数据功能没有回归。
